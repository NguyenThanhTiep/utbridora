## 5. Kiểm thử, bàn giao và thứ tự PR

1. Mỗi DEV chạy `npm ci`, `npm run build`, `npm run test:unit` trong `web-demo`; chạy Playwright spec liên quan trên fixture riêng. Cần test browser với 4 vai trò HR/Mentor/School/Student và backend thật cho luồng PUBLISHED/HIDDEN, lịch sử version, 409, sai assignment, refresh và file PENDING/CLEAN. Không ghi QA PASS từ self-test.
2. DEV05 PR HR/cohort/group/mentor → DEV06 PR School/HR policy/Case → DEV07 PR Mentor/Student, component và responsive. PR độc lập theo từng màn để giảm conflict; DEV07 ghép luồng cuối sau khi hai PR đầu đã review. QA03 test bản tích hợp, kiểm cả quyền, bàn phím và màn nhỏ. Sau merge, người phụ trách staging deploy theo quy trình riêng rồi smoke test URL demo với bốn vai trò; code merge không tự đồng nghĩa bản đang chạy đã cập nhật.
3. Bàn giao tối thiểu mỗi PR: trang/route web demo, FR/contract, API thật hoặc blocker, ảnh desktop/mobile trước và sau, kết quả build/unit/E2E, ca lỗi 401/403/409; Figma screen ID là tham chiếu tùy chọn. Chỉ người được phân quyền merge vào `main` sau review, QA và CI.
